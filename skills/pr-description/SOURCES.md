# Sources — pr-description

- Job: draft PR bodies from **committed** branch changes (file list + diff vs base); fixed Why: / How: / Testing: labels; diagrams when structure matters (fenced with ---); honest testing.
- Style: personal always-on prefs (first principles, high-level before detail, plain words).
- Shape: always `Why:` then `How:` then `Testing:` (same labels, same order) — e.g. config whitelist one-liners and larger code PRs alike.
- Tooling: Skillet (`spec.md` + `SKILL.md` + `evals/cases` + `references/shape.md`), modeled on skillet `examples/commit-conventions`.
